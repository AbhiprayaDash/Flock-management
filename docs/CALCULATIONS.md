# Calculation conventions

- Dates are ISO local calendar dates; placement is day 1. Store a batch timezone copied from the farm and use it consistently. Checkpoint times are local; there is no background notification service.
- Multiple logs are **incremental entries**, not cumulative daily meter readings. Feed offered − remaining − wastage = consumption for that entry. Optional meter readings are observations, not automatically converted to consumption. Do not submit a cumulative total twice. Date gaps remain gaps.
- Live inventory = initial placed + explicit placement/transfer-in events − recorded mortality − culls − company-pickup/legacy-sale/transfer-out/removal events. If any recorded log omits mortality or culls, current inventory is unavailable. Missing historical days still reduce confidence: totals only cover recorded periods.
- Livability = (initial + additional placements − mortality − culls) / (initial + additional placements) × 100. Company pickups and transfers out are not biological losses; historical sale records retain their earlier inventory meaning.
- FCR numerator = recorded cumulative consumed feed, kg. Denominator = current measured live biomass + removal biomass − initial biomass − incoming biomass, kg. All incoming/outgoing event weights are required. Suppressed if latest logged date differs from latest sample date, gain ≤ 0 or live inventory is unknown. This convention does not assign feed between partially marketed cohorts. When record dates and movement timing are inconsistent, treat FCR as unsuitable for comparison.
- Body weight is latest measured sample mean only; no interpolation. ADG = difference between last two means × 1000 / elapsed calendar days. CV = population standard deviation of individual weights / mean × 100. Individual-weight entry UI is pending.
- Stock density = current live birds / area; kg density uses latest sample and should be read with its measurement date. Stock balance = deliveries − recorded consumed feed. Reconcile physically: historic consumption may be missing. Feed days-remaining estimate is not yet implemented.
- Water/feed = total recorded litres / total recorded consumed kg. Not a matched-period ratio if either input has gaps. Blank is not zero. Zero feed gives no ratio.
- Data completeness is the percent of recorded entries containing feed, water, mortality and culls. It does not measure missing days, biological quality or diagnostic confidence. Quality score is withheld; no validated breeder curves or season profiles are included.
- Late corrections update the original row and recompute metrics from records, not cached totals. The production database retains old/new JSON with actor and timestamp. Optimistic revision checks reject conflicting API edits. Demo mode has no secure audit.
- Withdrawal date = final administration local date + verified withdrawal days. Unknown period stays unresolved. No default withdrawal period is invented. Eligibility labels are informational and do not constitute a marketing authorization; there is no sale-blocking workflow yet.
